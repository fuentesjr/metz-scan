## Known limitation (accepted trade-off, not a blocker): absent-`inherit_gem` excludes

When a target's file-scope `Exclude` is declared **only inside an `inherit_gem`'d
config whose gem is not present in the bundle running metz-scan** (e.g. Rails 8's
default `rubocop-rails-omakase`, which sets `AllCops: Exclude: data/**/*`), that
exclude is **silently not applied** in default mode. Reproduced:

```
# .rubocop.yml: `inherit_gem: { rubocop-rails-omakase: rubocop.yml }` (gem absent)
# default scan includes data/excluded.rb (exclude NOT honored)
# vs a local `AllCops: Exclude: [data/**/*]` — data/excluded.rb correctly excluded
```

Why this is accepted, not a headline defect for this round:
- It is the **documented trade-off** of the A fix — the scope-only loader can't
  read an absent gem's config file (`docs/ddrs/2026-07-08-rubocop-scope-only-config.md`).
- It is **strictly better than before**: these targets previously *crashed*,
  honoring no scope at all.
- It had **zero observable effect** on all five real codebases (maybe has no
  top-level `data/`; the others declare excludes locally or have the gem
  installed) — it reproduces only via a synthetic fixture.
- It does **not** manifest in the documented install path (metz-scan in the
  target's own Gemfile, where the omakase gem is present and excludes apply).

Follow-up (queued, not release-blocking): when default mode encounters an
`inherit_gem`/`plugins:`/`require:` reference it cannot resolve, emit a one-line
warning ("excludes from `<gem>` are not applied; install it or use `--all-cops`")
instead of silently degrading — turning silent degrade into loud degrade,
consistent with the DDR's "no silent degrade" principle. Plus a README note.
