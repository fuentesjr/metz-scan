# v0.5.0 Release Notes

Release notes for the `metz-scan` and `rubocop-metz` `v0.5.0` release.

## Highlights

- Fixes #31: `metz-scan scan` now defaults to Metz cops plus default-output
  project analyzers regardless of the scanned project's `.rubocop.yml`, so
  Metz findings are no longer buried under stock RuboCop output. The new
  `--all-cops` flag restores the previous full-suite behavior, and auto-fix
  follows the same policy. In default mode a target project's own Metz
  threshold overrides are ignored; use `--all-cops` to read the project
  config.
- Fixes #32: the `rubocop-metz` default config disables
  `Metrics/ClassLength`, `Metrics/MethodLength`, and
  `Metrics/ParameterLists`, which duplicated the corresponding Metz cops.
- Adds `--print-baseline` for scope-matched calibration baselines, plus
  baseline-delta reporting against a tracked full-manifest baseline.
- Adds an in-repo `metz-scan` consumer agent skill and README guidance for
  agent-driven usage.

## Release Readiness

- Both gems now report `0.5.0`.
- This is a default-behavior change: scans that relied on the old
  full-suite default must pass `--all-cops`.
- Candidate analyzers remain opt-in behind `--project-analyzers`.
- `rubocop-metz` publishes before `metz-scan`, matching the dependency
  direction.
