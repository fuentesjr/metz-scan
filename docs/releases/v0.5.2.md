# v0.5.2 Release Notes

Release notes for the `metz-scan` and `rubocop-metz` `v0.5.2` release.

This is a bug-fix release resolving default-scan file-scope defects found after
the `v0.5.1` release. There are no behavior-policy or threshold changes.

## Highlights

- Fixes #37: a default (Metz-only) `metz-scan scan` now honors the target
  project's per-cop `Exclude` (e.g. `Metz/*: Exclude`) in addition to the
  `AllCops: Exclude` already honored since #33. Default mode post-filters
  offenses through `ProjectCopScope.honor`, dropping any (cop, file) pair the
  project config scopes off via RuboCop's own `excluded_file?` and
  recomputing the offense count. Thresholds, enablement, and severity remain
  forced to Metz defaults; `--all-cops` is unchanged. A project that scopes
  the length cops off its test trees no longer gets flooded with test-file
  offenses on a default `metz-scan scan .`, while Metz opinions that still
  apply to test code (e.g. `DemeterTrainWreck`) continue to report.
- Fixes the `v0.5.1`/pre-release `v0.5.2` regression where default scans could
  crash on target projects whose `.rubocop.yml` references external RuboCop
  extension gems through `plugins:`, `require:`, or `inherit_gem:` that are not
  installed in the bundle running `metz-scan`. Default mode now reads only
  target file-scope settings, so local `AllCops: Exclude` and `Metz/*: Exclude`
  still apply without loading target extensions. `--all-cops` remains the full
  RuboCop mode and still requires the target's declared extensions to be
  installed.
- Fixes load-error reporting: missing target RuboCop extensions are no longer
  mislabeled as `rubocop-metz` load failures, and extensionless
  `bin/metz-scan` stack frames are stripped from concise CLI errors.
- Fixes false `Lint/Syntax` offenses in default mode: `--force-default-config`
  no longer discards the target's `TargetRubyVersion`, so modern Ruby (3.1+)
  syntax such as anonymous block/argument forwarding parses correctly instead of
  being flagged as a syntax error by the fallback parser. Default mode carries
  the target's declared or detected Ruby version through
  `RUBOCOP_TARGET_RUBY_VERSION`.
- Fixes `Metz/ControllersTooManyDirectCollaborators` over-counting: exception
  classes raised at `raise`/`fail` sites (mirroring the existing `rescue`-site
  exclusion) and the `Arel` SQL helper no longer count as direct collaborators,
  matching the `#34` fix for the sibling case.
- Default mode now emits a one-line warning when a target's `.rubocop.yml`
  inherits scope from an `inherit_gem` whose gem is not installed, instead of
  silently dropping that gem's `Exclude` — so a Rails 8 omakase project scanned
  from a bundle without the omakase gem is told its excludes are not applied.

## Release Readiness

- Both gems now report `0.5.2`.
- No behavior-policy or threshold change from `0.5.1`; the changes reduce
  crashes, false positives, and misleading error/output only.
- Gem metadata adds `changelog_uri` (releases page) and `bug_tracker_uri`
  (issues) links, and `rubocop-metz` now ships its `LICENSE` file.
- Dogfooding exit criterion 2 passed on the fixed HEAD across five real
  codebases (`docs/dogfooding/2026-07-08-round-0.5.2-reverify.md`).
- `rubocop-metz` publishes before `metz-scan`, matching the dependency
  direction.
