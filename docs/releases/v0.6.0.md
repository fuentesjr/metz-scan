# v0.6.0 Release Notes

Release notes for the `metz-scan` and `rubocop-metz` `v0.6.0` release.

This is a minor release: two new cops are enabled by default, usage errors
change exit code, and `rubocop-metz` now requires RuboCop 1.90.

## Upgrade notes

- **New default cops.** `Metz/GodServiceClass` flags `*Service` classes with
  more than one public method besides `initialize`, and
  `Metz/OperationsTooManyPublicMethods` does the same for classes under
  `app/services` or `app/operations`. Expect new findings in projects with
  multi-method service objects. In a default scan, only a per-cop `Exclude`
  takes effect; `Enabled: false` and `MaxPublicMethods` apply under
  `--all-cops` and plain `rubocop`.
- **Exit code 64 for usage errors.** A mistyped flag, path, or subcommand, or
  an invalid report file, now exits 64 instead of 1 in every subcommand.
  Exit 1 still means findings were reported, and 2 still means RuboCop
  failed. Scripts that treated 1 as "anything went wrong" should check for
  64 too.
- **RuboCop `~> 1.90`** (was `~> 1.80`).

## Changes

- The default scan lists findings hidden by inline disables or per-cop
  `Exclude`, with each suppression's reason or the lack of one: a JSON
  `suppressions` array and a "Suppressed findings" text section. They stay
  out of offense counts, compliance, and the exit code (#53).
- The default scan honors `inherit_mode: merge: [Exclude]`, so it no longer
  reports files that `--all-cops` and plain `rubocop` exclude (#52).
- `rules --bogus` and `explain --bogus` no longer crash, and
  `scan --auto-fix` now rejects an invalid `--format` (#54).
- `scan --auto-fix --dry-run` no longer leaves corrections applied when the
  target directory contains a read-only file (#62).
- Three opt-in testing-discipline cops, disabled by default:
  `Metz/TestReachesPrivate`, `Metz/TestAssertsOnInternals`, and
  `Metz/TestStubsSubject` (RSpec only).
- Candidate project analyzer `MetzProject/TestCallsPrivateMethod` (opt-in;
  needs the optional `rubydex` group).
- The optional `rubydex` backend supports rubydex 0.4.
- Both gemspecs evaluate from any working directory and in Dependabot's
  sparse checkout (#41).
