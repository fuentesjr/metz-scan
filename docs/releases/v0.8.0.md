# v0.8.0 Release Notes

Release notes for the `metz-scan` and `rubocop-metz` `v0.8.0` release.

This is a minor release: `scan` gains `--baseline` delta filtering, `--auto-fix`
and its companion flags are removed, and four `Metz/*` cop messages now name
their target method or class.

## Upgrade notes

- **`--auto-fix`, `--unsafe`, and `--dry-run` are removed.** Metz design rules
  need human or agent judgment rather than mechanical autocorrection. Passing
  any of these flags is now a usage error (exit 64) (#138).
- **Cop messages name their target.** `Metz/MethodsTooLong`,
  `Metz/ClassesTooLong`, `Metz/MethodsTooManyParameters`, and
  `Metz/OperationsTooManyPublicMethods` messages now include the method or
  class name. Tooling that matches exact message text needs updating (#138).

## Changes

- `metz-scan scan PATH... --baseline FILE` compares against a saved JSON report
  and reports only new or grown findings and new or changed suppressions across
  text, JSON, SARIF, and gh-annotations output, replacing the shell recipes in
  `skills/metz-scan/SKILL.md` (#138).
- `metz-scan explain` describes `MetzProject/*` project analyzers as well as
  `Metz/*` cops (#138).
- Project analyzers share one parse per file through a per-run source cache
  that honors each file's `TargetRubyVersion` (#138).
- Dependency bumps: `rubocop` 1.92.3 (#136).
