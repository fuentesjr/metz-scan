# v0.7.0 Release Notes

Release notes for the `metz-scan` and `rubocop-metz` `v0.7.0` release.

This is a minor release: both gems now require Ruby `>= 4.0`, `scan` ignores
`.rubocop` option files and `RUBOCOP_OPTS`, default scans honor `Enabled: false`
and widened or replaced per-cop `Include`, and JSON reports move per-cop
guidance to a top-level `guidance` map.

## Upgrade notes

- **Ruby `>= 4.0`** (was `>= 3.3`) (#81).
- **`.rubocop` and `RUBOCOP_OPTS` are ignored in every scan mode.** `scan` and
  `scan --auto-fix` invoke `RuboCop::Runner` directly instead of parsing
  [RuboCop](https://rubocop.org/) CLI flag files, and print one `metz-scan: note:` line to stderr when
  either source is non-empty. Move any intended settings to `.rubocop.yml`;
  operational variables such as `RUBOCOP_CACHE_ROOT` and
  `PARALLEL_PROCESSOR_COUNT` still apply (#127).
- **Per-cop `Include` now widens and replaces in default mode.** Writing a
  per-cop `Include` without `inherit_mode: merge: [Include]` now replaces the
  cop's stock scope in default `scan`, matching `--all-cops` and plain
  `rubocop` (#127).
- **Exit 2 when `scan` cannot check code.** Invalid project `.rubocop.yml`
  configs, RuboCop or internal errors, and scans that inspect zero files now
  exit 2 with an empty stdout instead of reporting a clean scan (#67, #86).
- **JSON `guidance` map.** Per-cop `why_it_matters`, `fix_safety`, and
  `suggested_next_moves` move from every offense object to a top-level
  `guidance` hash keyed by cop name (#75).
- **Calibration tooling is no longer packaged in the `metz-scan` gem.** It
  remains in the repository under `tools/lib/` (#85).

## Changes

- Default `scan` honors `Enabled: false` for `Metz/*` cops, the `Metz`
  department, and `MetzProject/*` project analyzers, recording hidden findings
  as `config_disabled` in the suppression ledger (#70, #71, #79).
- Project analyzers support `MetzProject/*` `Exclude` entries and inline
  `# metz-scan:disable` directives across scan modes, and under `--all-cops`
  they follow full `RuboCop::ConfigStore` scope including remote `inherit_from`
  suppressions (#79, #127).
- Default `scan` preserves per-cop, `AllCops`, and inherited `inherit_mode`,
  rewrites inherited relative `Include` globs across `.rubocop*` chains, and
  discovers `.erb`, `.haml`, and `.slim` templates matched by
  `Metz/ViewsDeepNavigation`'s effective `Include` scope (#127).
- Default `scan --auto-fix` and `--dry-run` share target discovery and scope
  with `scan`, honoring `AllCops: Exclude`, per-cop `Exclude`, `Enabled: false`,
  view templates, `TargetRubyVersion`, and exit 2 on zero inspected files (#127).
- `--all-cops` adds stock RuboCop cop descriptions to JSON `guidance`, text,
  and live [SARIF](https://docs.oasis-open.org/sarif/sarif/v2.1.0/sarif-v2.1.0.html) output; `metz-scan report` populates `Metz/*` guidance when
  rendering raw `rubocop --format json` files and exits 64 on non-report JSON
  (#66, #77, #127).
- Default `scan` prints a one-line stderr note when anchored path-scoped cop
  `Include` globs miss files under a nested project root (#76).
- Closed accuracy gaps in `rubocop-metz` cops and view extractors, moved
  `Metz/OperationsTooManyPublicMethods` path scoping to `relevant_file?`, and
  declared `AllowedReceivers` for `Metz/ViewsDeepNavigation` (#87, #127).
- Enabled `rubygems_mfa_required` in both gemspecs (#85) and trimmed
  `skills/metz-scan/SKILL.md` for lower agent context cost (#72, #74, #80).
