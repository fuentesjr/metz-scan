# v0.5.1 Release Notes

Release notes for the `metz-scan` and `rubocop-metz` `v0.5.1` release.

This is a bug-fix release resolving the two headline-UX defects found in the
`0.5.0` dogfooding round (`docs/dogfooding/2026-07-05-round-0.5.0.md`). There
are no behavior-policy or threshold changes.

## Highlights

- Fixes #33: a default (Metz-only) `metz-scan scan` now honors the target
  project's `AllCops: Exclude` while still forcing Metz cop defaults. File
  selection is read from the project config first, then Metz cops run against
  that explicit file list, so project excludes are respected without letting
  project thresholds or disables override stock Metz defaults. Invalid project
  config still falls back to forced-default target discovery.
- Fixes #34: `Metz/ControllersTooManyDirectCollaborators` no longer counts
  rescue-clause exception classes, constants owned by the enclosing controller
  class (including qualified and `self::` assignments), or a small
  framework/stdlib root-name allowlist as collaborators. The offense message
  now reads `Controller method` instead of mislabeling every method `Action`.

## Release Readiness

- Both gems now report `0.5.1`.
- No default-behavior change from `0.5.0`; both fixes reduce false positives
  and misleading output only.
- `rubocop-metz` publishes before `metz-scan`, matching the dependency
  direction.
